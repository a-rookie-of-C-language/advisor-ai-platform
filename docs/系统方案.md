## 3. student-service 设计方案

### 3.1 技术选型

- Java 17 + Spring Boot 3.3.4
- Spring Cloud 2023.0.3
- MySQL（与现有服务共用数据库或独立数据库）
- Redis（缓存）
- Spring Data JPA / MyBatis-Plus（待定）
- EasyExcel（Excel 导入导出）
- OpenFeign（调用 auth-service、risk-control-service、audit-service）

### 3.2 数据库设计

#### 3.2.1 核心表结构

**学生主档表（student_profile）：**

```sql
CREATE TABLE student_profile (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '主键ID',
    student_no      VARCHAR(32) NOT NULL UNIQUE COMMENT '学号（业务唯一键）',
    name            VARCHAR(64) NOT NULL COMMENT '姓名',
    gender          TINYINT COMMENT '性别：0-女，1-男',
    grade           VARCHAR(16) COMMENT '年级',
    major           VARCHAR(128) COMMENT '专业',
    class_code      VARCHAR(64) COMMENT '班级编码',
    counselor_no    VARCHAR(32) COMMENT '辅导员工号',

    -- 联系方式
    phone           VARCHAR(32) COMMENT '手机号',
    email           VARCHAR(128) COMMENT '邮箱',
    dormitory       VARCHAR(128) COMMENT '宿舍地址',
    emergency_contact VARCHAR(256) COMMENT '紧急联系人',

    -- 扩展预留
    extra_data      JSON COMMENT '扩展数据JSON',

    -- 状态
    info_completeness TINYINT DEFAULT 0 COMMENT '信息完整度：0-完整，1-部分缺失，2-严重缺失',
    risk_level      TINYINT DEFAULT 0 COMMENT '风险等级：0-正常，1-关注，2-预警，3-严重',

    -- 审计字段
    created_by      VARCHAR(64) COMMENT '创建人',
    created_at      DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updated_by      VARCHAR(64) COMMENT '更新人',
    updated_at      DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    deleted         TINYINT DEFAULT 0 COMMENT '逻辑删除',
    version         INT DEFAULT 0 COMMENT '乐观锁版本',

    INDEX idx_class_code (class_code),
    INDEX idx_counselor_no (counselor_no),
    INDEX idx_grade (grade),
    INDEX idx_info_completeness (info_completeness),
    INDEX idx_risk_level (risk_level)
) COMMENT '学生档案表';
```

**学生待办表（student_task）：**

```sql
CREATE TABLE student_task (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '主键ID',

    assignee_no     VARCHAR(32) COMMENT '处理人工号',
    assignee_name   VARCHAR(64) COMMENT '处理人姓名',

    description     TEXT COMMENT '任务描述',
    handle_note     TEXT COMMENT '处理备注',
    handle_time     DATETIME COMMENT '处理时间',

    created_by      VARCHAR(64) COMMENT '创建人',
    created_at      DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_by      VARCHAR(64) COMMENT '更新人',
    updated_at      DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,

    INDEX idx_student_id (student_id),
    INDEX idx_task_status (task_status),
    INDEX idx_assignee_no (assignee_no),

```

### 3.5 核心业务流程

#### 3.5.1 Excel 导入流程

```
用户上传Excel
    │
    ▼
解析Excel → 校验必填字段
    │
    ▼
风控校验（risk-control-service）
    │
    ▼
按学号查重
    │
    ├─ 存在 → 用户选择覆盖/跳过
    │
    └─ 不存在 → 新增档案
    │
    ▼
自动检测信息完整度
    │
    ▼
信息缺失 → 自动生成待办
    │
    ▼
写入学期快照（batch）
    │
    ▼
记录导入批次
    │
    ▼
返回导入结果（成功/失败/重复明细）
```

#### 3.5.2 待办生成流程

```
导入完成/信息变更
    │
    ▼
检测信息完整度
    │
    ├─ 完整（手机号/邮箱/宿舍/紧急联系人至少有一个）→ 不生成待办
    │
    └─ 不完整 → 查询是否存在未关闭的信息缺失待办
                    │
                    ├─ 存在 → 更新待办
                    │
                    └─ 不存在 → 新增待办（归属班级辅导员）
                                    │
                                    ▼
                            写入审计日志（audit-service）
```

### 5.5 与打卡模块对接

**对接方式：**

- 方式一（推荐）：打卡模块通过 API 主动推送考勤数据到 attendance-service
- 方式二：attendance-service 定时通过 API 拉取打卡模块数据

**数据格式约定：**

```json
{
  "studentNo": "2023010101",
  "courseName": "高等数学",
  "attendDate": "2026-05-07",
  "status": 1,
  "checkInTime": "2026-05-07 08:15:00"
}
```

**状态码：**

| 值 | 状态 | 说明 |
|------|------|------|
| 0 | 正常 | 按规定时间打卡 |
| 1 | 迟到 | 超过规定时间打卡 |
| 2 | 缺勤 | 未打卡且无请假 |
| 3 | 早退 | 提前离开 |
| 4 | 请假 | 已请假并审批 |

### 5.6 异常自动生成逻辑

```
定时任务（每日凌晨）
    │
    ▼
统计昨日考勤数据
    │
    ▼
查询缺勤/迟到/早退记录
    │
    ▼
按规则检测异常
    │
    ├─ 连续缺勤 ≥ 3 次 → 生成待办
    │
    ├─ 月度缺勤率 > 20% → 生成预警待办
    │
    └─ 其他 → 记录但不生成待办
    │
    ▼
写入 attendance_incident 表
    │
    ▼
通知辅导员（预留）
```

## 10. 风险与注意事项

### 10.1 数据隔离

- student-service 与现有服务共用 auth-service 时，确保用户身份数据一致性
- 辅导员与学生的归属关系需要在 auth-service 中有对应账号体系支撑

### 10.2 Excel 导入性能

- 千级数据量建议分批处理（每批 500 条）
- 大文件导入使用异步任务，避免 HTTP 超时

### 10.3 敏感信息

- 联系方式在 API 响应中按角色过滤，发送给 agent 时自动脱敏
- 导出功能记录审计日志

### 10.4 后续扩展

- 学业/出勤/心理等状态域接入时，通过 student-service 统一管理学生 ID，避免数据孤岛
- Agent 工具接口预留好，待 chat-service 接入时直接对接
